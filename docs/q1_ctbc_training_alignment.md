## 生效参数差异

“修改前默认”表示不传 `--ctbc_stage`、不传 `--num_envs`、从头训练。显式传入 `--ctbc_stage=stairs` 时，修改前与参考运行唯一的可配置参数差异为环境数。

| 项目 | 桌面 log 那次训练 | 修改前默认 | 本次对齐后默认 |
|---|---|---|---|
| 阶段 | `stairs` | `single` | `stairs` |
| 并行环境数 | 1024 | 4096 | 1024 |
| 连续台阶数 | 3 | 1 | 3 |
| 单级高度范围 | 4–12 cm | 2.5–8 cm | 4–12 cm |

| 默认运行名称 | `stairs` | `single` | `stairs` |
| 每轮采样量（环境数 × 48 步） | 49,152 | 196,608 | 49,152 |
| PPO 每个小批次（每轮分 4 份） | 12,288 | 49,152 | 12,288 |

旧快照中的 Python 源码同样默认 `single`，实际保存的运行选择了 `stairs`。本次将默认入口也调整为该运行的阶段，避免只改环境数后仍启动单阶。

前馈仍按累计更新轮数退火。环境数从 1024 增到 4096 时，前 3000 轮全强度指导覆盖的采样量从 147,456,000 增到 589,824,000；第 15000 轮指导归零时，累计采样量从 737,280,000 增到 2,949,120,000。因此保持相同轮数并不保持相同采样量。这可能影响优化过程和课程进展，无法仅凭配置判定它导致了效果变差。

## 对齐范围与启动方式

`q1_ctbc` 的配置和无阶段参数启动均采用上述参考设置。显式 `--ctbc_stage=single`、`robust`、`stairs20` 继续可用。`q1` 的 T0 任务和 `q1_ctbc_highcom` 通过独立环境数配置保留原来的 4096；高站姿任务默认仍为 `single`。

在项目根目录、已安装 Isaac Gym 的训练环境运行：

```bash
python wheel_legged_gym/scripts/train.py --task=q1_ctbc --ctbc_stage=stairs --num_envs=1024 --seed=1 --max_iterations=30000 --headless
```

以上参数现已是默认值，简写为 `python wheel_legged_gym/scripts/train.py --task=q1_ctbc --headless` 也会选中同一基线。命令行显式覆盖仍优先。

`--resume` 会恢复所选检查点旁的保存配置，可能带回 4096 环境或其他阶段；本次默认值修改不覆盖已有运行的历史配置。桌面 `log` 没有 `model_*.pt`，无法据此恢复原权重、优化器或累计迭代数。参考快照的 `resume=false`，复现其设置应从头训练。

当前机器没有 Isaac Gym，未实际重跑训练。配置等价和 CPU 回归不能保证重现相同成功率；旧目录也未保存 PPO/runner 源码、依赖版本和完整运行状态，这些无法逐项追溯。
